# QAT Toolkit: Kara David's Wish Note

## Repository Overview

This QAT (Quality Assurance Testing) toolkit documents the functional testing of an AI-generated PHP web application backed by a MariaDB database. The test case in this repository is derived from the source file `textcase.txt`.

The repository contains three parts:

- **Part A:** This readme file, containing the test case for an AI-generated web application
- **Part B:** The AI prompt used to create the test web application, named `webapp-generation-prompt.txt`
- **Part C:** The single-file PHP web application generated by AI, named `test-webapp.php`

## Test Case Documentation

### Test Case Summary

| Field | Details |
|---|---|
| **Test Case ID** | TC-DataEntry-001 |
| **Test Case Title** | Data Entry - Valid |
| **Description** | Functional testing of the Data Entry page with backend validation using MySQL queries |
| **Status** | Failed |

### Preconditions

- The Kara David Birthday Wishnote App is installed locally.
- The MySQL database is pre-populated for comparison.
- The Data Entry page is accessed in the latest Chrome or Firefox browser.

### Test Data

Five (5) valid entries containing First Name, Last Name, Government Position, and Location, all within their maximum character limits.

### Test Execution

| Step | Action | Expected Result | Actual Result |
|---|---|---|---|
| a | Verify that the form contains labels in proper order and the text boxes are writable | The form contains labels in this order: "Target's First Name", "Target's Last Name", "Target's Government Position", and "Target's Location"; all text boxes are writable | The form contains labels in this order: "Target's First Name", "Target's Last Name", "Target's Government Position", and "Target's Location"; all text boxes are writable |
| b | Verify the "Send Wish Note" button | The "Send Wish Note" button changes color on hover and is not disabled | The "Send Wish Note" button changes color on hover and is not disabled |
| c | Enter test data on their respective fields | The respective fields accept data entries of valid test data | The respective fields accept data entries of valid test data |
| d | Click the "Send Wish Note" button | A modal titled "Verify Target Data" appears in the center of the screen | A modal titled "Verify Target Data" appeared in the center of the screen |
| e | Verify that the modal contains the same entry as the test data | The modal shows the same First Name, Last Name, Government Position, and Location that were entered | The modal showed the same First Name, Last Name, Government Position, and Location that were entered |
| f | Click the Cancel button | The modal closes and the form keeps the entered data | The modal closed and the form kept the entered data |
| g | Click "Send Wish Note" again, then click "Confirm and Send" in the modal | The modal appears again, and clicking "Confirm and Send" submits the form | The modal appeared again, and clicking "Confirm and Send" submitted the form |
| h | Verify that a successful entry message shows on the Data Entry page | The message "Success! The wish note has been sent." appears above the form | The message "Success! The wish note has been sent." appeared above the form |
| i | Verify that the test data shows in the database | All four values (First Name, Last Name, Government Position, and Location) appear in the table `main_corrupt_politicians` | Query used: `SELECT * FROM main_corrupt_politicians;`. First Name, Last Name, and Government Position were saved, but the Location column is NULL for all five entries |

### Defect Summary

The application saves First Name, Last Name, and Government Position, but not Location. The Location column is omitted from both the SQL `INSERT` statement and the `bind_param` call in `test-webapp.php`. The user sees a success message while the Location data is silently lost, so step i fails and the overall test status is **Failed**.
